The versions

Four versions in ten days — what changed, and why

v1 · audit workbench
Question cards, clause matrix, review queue, chat, model tables
Every feature defensible; the sum not what a legal team reaches for. Cut.
v2 · file converter
Drop in → one result line → findings marked on the PDF → corrected copy
“Until they see the PDF itself they will not trust the system.”
v3 · knowledge graph
Neo4j as the RAG store beside Postgres; register from GLEIF; models read the graph’s selection
The two questions are graph patterns. Database-first, not LLM-extracted.
v4 · graph only
Neo4j the sole database; scoped-then-full verification; 3 steps + a Technik page
One system to run. Precision restored. Explainable to engineers and lawyers.
What stayed through all four: the rule layer, the full-text verifier, the corporate guideline as a file, the measured precision/recall on real contracts (CUAD).

The graph

The database is the knowledge graph

database-first
Seeded from files and registers, not from a model: the guideline (Legal’s file), the taxonomy, GLEIF — the public LEI register records Arvato Payment Solutions GmbH as the previous name of Riverty GmbH — and the team’s decisions.
retrieval inside the graph
Every clause carries its embedding (768 d, cosine, Cypher SEARCH) and its text (Lucene). Hybrid = reciprocal rank fusion of both; scoped by graph filters.
why not …
Postgres + pgvector (v1–v3): the questions became joins over label tables, knowledge lived in JSON. Cosmos DB Gremlin: no native vectors, Gremlin. AGE on Azure PostgreSQL: the Microsoft runner-up — swaps in for two modules.
Live numbers on the Technik page: nodes, edges, and how many gaps the pattern finds right now.

Check

Rules for recall, the model for precision

routing by risk
Pro · high verify · read handwriting
Flash · low/medium label · extract · draft · locate
Flash-Lite injection screen
temperature 0, schema-validated outputs; LLM_PROVIDER=foundry → GPT-5 deployments, same table
why two reads
Always full: ~5× the tokens, no scale to 300-page agreements. Only scoped: over-flags. The pair keeps the measured precision at a fifth of the cost.
degrades honestly
No key or an outage → the rule result stands, marked “ohne KI-Gegenprüfung”, repeated at the next start. Quota hit → fail fast, don’t hang.

The UI

Three steps — the PDF is the interface

1 · Hochladendrop one or many · one result line each · a filter for “which contracts lack X”
2 · Prüfenmarkers on the page · one finding at a time · Übernehmen / Nicht zutreffend
3 · Herunterladenwhat was applied · the copy · preview · filing
Why one finding at a time. The only clicks are decisions; a decision moves on; the marker on the page is verified with a glance — a list would send the lawyer back into the PDF.
Why no numbers for lawyers. No confidences, no traces on these pages — quote, reason, marker, and whether it was cross-checked. German first, English one click.
Why a Technik page. Engineers get the same 14 stages with module, model, thresholds, the graph’s live counts and a trace of one contract — generated, so it cannot drift.

Adoption

How the legal team gets the most out of it

trust
Nothing is changed by the machine. The original is never touched; every decision is a named person’s; the audit log answers “who accepted what, when, on which file”.
learning
So funktioniert es for the team, Technik for IT and audit — both generated from the code. Half an hour of onboarding: drop, decide, download.
measure
Minutes per contract, review rate per class of finding, findings per 1,000 pages, and precision/recall against the answer key — reported, not asserted.
honest limits
Drafts are starting points. Handwriting depends on the vision model. A missing clause goes on an addendum page — a PDF does not reflow.
